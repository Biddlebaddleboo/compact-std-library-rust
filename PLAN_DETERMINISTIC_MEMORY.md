# PLAN_DETERMINISTIC_MEMORY.md — Ownership and Leak-Free Reclamation

## Objective and starting scope
Create deterministic individual-object allocation/release/reuse policy with rigorous no-stranded-memory guarantees and minimal global coordination. Read `crates/compact_backend_std/src/cage.rs`: `CageAllocation<T>`, `ReleaseGuard`, `ReleaseCollector`, `ReleaseBatchScope`, `release`, `release_extent`, `release_many`, `take_pending_reuse`, `AllocationHeader`, `read_header`, `read_owner_header`. Read `crates/compact_backend_std/src/allocator_model.rs`: `HypotheticalAllocator`, `ChunkGeneration`, `RemoteReleasePin`, `reserve_chunk`, `release_allocation`, `begin_remote_release`, `commit_remote_release`, `thread_exit`, `quarantine_chunk`, `teardown_chunk`, `validate`. Own proposed new private `crates/compact_backend_std/src/deterministic_memory.rs` and isolated model tests. Region workstream exclusively modifies cage.rs and orchestrator controls lib.rs.

## Verified release behavior and original failure hypothesis
`release(offset)` derives `ReleaseExtent`, may queue it in active TLS ReleaseCollector, otherwise calls `release_many(&mut one)` discarding Result. `ReleaseCollector::flush_with` retries one-at-a-time on batch failure but then clears `len` even if retries fail. Audit *all* error/poison/invalid-offset paths before changing release handling. An ignored result is not proof of an ordinary leak, but cannot serve as a rigorous recovery guarantee.

## Phase 1 — contract and state machine
Define exact linearization and byte conservation for GlobalFree, ReservedUnused, Live, LocalPending, RemotePending, LocallyReusable, Reclaimable, Quarantined. Establish unique owner and release provenance, checked offset→region identity and generation/ABA protection, live/pending account rules, safe type-erased Drop, batch reentrancy, failed descriptor preservation, rollback on partial failure, quarantine behavior, and zero user destructor work under allocator locks. Logical death is immediate on Drop; eligible storage is synchronously reusable or in a bounded authoritative pending state with guaranteed deterministic drain. Clarify what happens on unexpected invalid metadata (fail visible/quarantine, never silently lose or unsafely recycle).

## Phase 2 — policy prototype
Implement proposed internal operations `allocate_local(layout)`, `recycle_local(extent)`, `release_remote(extent)`, `drain_pending(bound)`, `return_empty_region(region)` (names proposed, not verified symbols). Bounded size classes, lazy local reservations, deterministic fast compatible reuse and global fallback. Allocate/release independent objects; don't require whole region death for compatible block reuse. Cross-thread release must be acknowledged by stable record even after origin thread exit. Synchronous fallback never waits on worker. No unbounded queue allocation in Drop. Explicitly define how foreground work limits interact with capacity exhaustion and error returns.

## Tests and gates
Extend test model then prove actual mutex/atomic synchronization (model alone insufficient). Deterministic interleaving/barriers for remote release vs exit/reclaim, duplicate/stale release and address reuse, local and remote reuse, registry pin/removal, panic/unwind/poison, nested collector, allocation exhaustion and rollback, metadata creation failures, fragmented long-lived objects. Test exactly-once object destructor, non-overlapping live extents, byte conservation after each commit, and no lost descriptor on errors. Multiple allocation/drop cycles must return live bytes to zero and allow equivalent capacity reuse; thread churn must stabilize metadata and reserved slack. Quarantined regions must be reported, not misrepresented as reclaimed. No worker progress required.

## Handoff
Deliver concrete private module + tests, exact interfaces for region-owner cage.rs, correctness and recovery evidence, proof gaps and measured memory overhead. Do not implement or integrate unsafe code before central safety review. No public API or collection contract change without approval.

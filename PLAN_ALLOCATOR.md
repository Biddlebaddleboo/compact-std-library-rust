# PLAN_ALLOCATOR.md — Owner-Affine Chunk Allocator Prototype

## Objective and exact scope
Implement and evaluate bounded owner-affine local allocation in existing cage, seeking fewer global mutex acquisitions without data races, leakage or memory growth. Current 2-vCPU host sufficient. Own `crates/compact_backend_std/src/cage.rs`, `src/allocator_model.rs`, allocator tests. Start `Allocator`, `lock`, `CageAllocation<T>::allocate`, `allocate_block`, `allocate_from_cursor`, `take_pending_reuse`, `release_many_locked`, `ReleaseCollector::{take_compatible,flush}`, `read_header`, `validate_typed_header`. Read `ALLOCATOR_CONTRACT_V2_5.md`, `PROFILE_V2_5_BASELINE.md`, `PROFILE_V2_5_MEMORY.md`; shared benchmarks/collections read-only.

## Verified facts and non-goals
Global mutex/atomic overhead is dominant in B10; existing pending reuse does not solve it. Previous layout precomputation/header-after-unlock experiments regressed A2/other cases. Sequential test model is not a concurrency proof. Retain four-byte `CageAllocation<T>`, sixteen-byte header unless separately justified; no lock-free reclamation, unbounded per-thread arena or destructor under allocator lock.

## Phase 1 — close contract safety gates
Extend model for owner-affine, nontransferable chunks: GlobalFree, Reserved, Live, LocalPending, RemotePending, Retiring, Reclaiming, Reclaimed. Reject active chunk transfer; model exact owner and per-block byte conservation. Define unique allocation/release provenance, offset→chunk lookup, generation/stale duplicate-free prevention, registry removal vs in-flight remote release, mutex lock order and acquire/release publication, TLS destructor/reaper sequencing, nesting/reentrancy, panic, poisoned mutex, release errors, allocation failure, fragmentation, exhaustion and rollback. Counters: live including pending, reserved slack, global free, reclaimable, side metadata. Define coherent statistics snapshots and remaining_bytes semantics. Use deterministic barrier/model tests, central architecture review **before unsafe chunk implementation**.

## Phase 2 — isolated working prototype
Prototype lazy bounded chunk reservation through global lock; owner-affine TLS safe chunk handle with side metadata, local bump/reuse protected by chunk synchronization, large/odd allocations and cap/exhaustion through legacy global fallback. Maintain stable registry lookup by offset for remote drops; prefer registry mutex + synchronous chunk-state mutex, no unbounded queue. Remote paths pin record against reclamation; don't expose globally free subextents while siblings live. Keep header initialized/published safely. No user code/destructor under registry/global/chunk locks. On TLS exit close local allocation, flush pending, mark retiring; reaper only publishes whole interval when live/pending/in-flight all zero. Quarantine ambiguous/poisoned state safely and report rather than silently leak counters. A failed reservation/release must not corrupt free lists or lose a descriptor.

## Phase 3 — incremental measurements
Compare legacy, reservation-only, local reuse, remote-free, final accepted config; A2/B8/B10/B3/B5 plus full suite. Record lock acquisitions, median/p95, throughput, cycles/futex samples, RSS/idle reclaim, high-water, fragmentation, cached bytes and metadata. Primary B10 one and two workers, 4/8 oversubscription optional; do not require physical multicore purchase. Default ≤+2% retained, ≤+5% peak RSS. Keep global fallback if chunk budget reached.

## Required tests and decision
Deterministic concurrency schedules for simultaneous remote free vs owner exit/reclaim, duplicate/stale free/address reuse, nested collectors, panic/drop/reentrant code, exhausted/fragmented cage, thread churn and no-overlap live allocations; Miri supported cases, randomized stress and sanitizer/model checker if available. Document precise interface/ABI/memory changes and produce Accepted/Rejected/Blocked decision. If blocked, identify proof obligation and continue with independent workstreams. Report SHA, diff, tests and measured outcomes.

# PLAN_ALLOCATOR.md — Bounded Concurrent Allocation

## Objective and implementation scope
Reduce B10 global-mutex contention with a correctly synchronized, bounded owner-affine local chunk prototype, retaining exact accounting and remote-free safety. Own `crates/compact_backend_std/src/cage.rs`, `allocator_model.rs` and dedicated allocator tests. Start: `Allocator`, `lock`, `CageAllocation<T>::allocate`, `allocate_block`, `allocate_from_cursor`, `take_pending_reuse`, `release_many_locked`, `ReleaseCollector::{take_compatible,flush}`, `read_header`, `read_owner_header`, `validate_typed_header`. Read `ALLOCATOR_CONTRACT_V2_5.md`, `ALLOCATOR_PHASE1_V2_5.md`, `ALLOCATOR_OWNER_HEADER_V2_5_RESULTS.md`. Collections and benchmark harness read-only.

## Verified facts
Global mutex remains a B10 hotspot; new owner-header fast path is integrated. Sequential model does not prove real concurrency. Proposed chunks are owner-affine and non-transferable; chunk registry, provenance, teardown, accounting and memory bounds remain open. Preserve 4-byte owner, 16-byte header and fully checked typed raw-offset API.

## Phase 1 — ownership and safety contract
Audit every owner constructor, raw-offset reader, release caller, resize, pending reuse and cross-thread transfer. Prove unique owner/double-release handling or add side generation metadata. Extend model for chunk generation, Live, Local/RemotePending, in-flight registry pin, Retiring, Reclaiming and quarantine. Define linearization points, lock order (registry → global → chunk), publish/retire/reclaim synchronization, allocation commit/rollback, poisoned mutex, failed descriptor publication, nested collectors and reentrant Drop, TLS destructor/reaper sequencing, exact live (including pending) accounting and coherent snapshots. Test remote release vs retirement and registry removal, stale address reuse, failure/exhaustion, panic/unwind. Add a Loom-style actual synchronization model if available. Obtain central review **before unsafe production chunk code**.

## Phase 2 — bounded prototype
Design side-metadata `ChunkRecord` with cage interval, generation, home owner, state, counters, compatible reusable extents and mutex. Calculate per-chunk metadata and aggregate caps first. Lazily reserve through global allocator and publish stable registry entry; allocate locally under chunk mutex, falling back globally for unusual/large/cap-limited allocations. Route remote releases by checked offset→stable registry handle; pin against reclaim, then synchronously commit release with chunk lock. No unbounded release queue or allocation in Drop; preserve descriptor on error. Local chunk remains home-affine; on owner exit stop allocation, flush nested collectors, mark Retiring, then reclaim whole interval only after live/pending/pins zero. Never reclaim a subextent globally with siblings live; no user destructor under allocator locks. On ambiguous failure quarantine safely and report. Keep prior global allocator as fallback and comparison.

## Phase 3 — tests, profiling, acceptance
Deterministic barriers/interleavings, synthetic model, Miri-valid cases, native concurrency stress, remote frees/exit, nested collectors, panic, alignment, exhaustion, reclamation and no-overlapping-live-extents/accounting tests. Compare baseline, reservation, local reuse and remote release variants separately. Profile A2/B3/B5/B8/B10, locks, throughput, 1/2 worker median/p95/cycles and fragmented/idle memory. 4/8-worker tests only optional oversubscribed stress. Memory ≤+2% retained and ≤+5% peak RSS, bounded metadata/slack, stable idle RSS; any exceptions need approval. Accept only verified overall gain and soundness; otherwise reject or label precise blocker. Report source SHA, diff, tests, measured deltas, safety proof and unresolved issues.
